## 三、核心设计思路

### 3.1 LLM客户端封装设计

**设计原则：策略模式 + 工厂模式 + 懒加载**

```
┌─────────────────────────────────────────────────────────────┐
│                        LLMClient                             │
│                                                             │
│  _create_llm() 策略分发：                                     │
│  ├─ deepseek  → ChatDeepSeek                                │
│  ├─ qwen      → ChatDashScope                               │
│  └─ openai    → ChatOpenAI                                  │
│                                                             │
│  对外接口：                                                   │
│  ├─ chat(messages)         # 同步对话                        │
│  ├─ stream_chat(messages)  # 流式对话                        │
│  ├─ get_llm()              # LangChain兼容实例               │
│  └─ from_config()          # 类方法：从配置创建              │
│                                                             │
│  输入格式（统一）：                                           │
│  [{"role": "system/user/assistant", "content": "..."}]      │
└─────────────────────────────────────────────────────────────┘
```

**关键实现技巧：**
- `_convert_messages()` 统一转换为LangChain消息对象（Human/AIMessage/SystemMessage）
- `from_config()` 类方法实现便捷初始化，避免各处重复加载配置
- `stream_chat()` 处理多种chunk格式，兼容不同LLM供应商的输出差异
- 内置详细自测脚本，支持无API Key环境下的模块测试

### 3.4 LCEL链式调用编排

**设计原则：函数式编程、6步流水线、可独立测试**

```
DietAgentChain 处理流水线：
┌─────────────┐     ┌─────────────┐     ┌─────────────┐
│  用户查询    │────▶│ 信息收集    │────▶│ 知识检索    │
│ (user_query)│     │ step_1()    │     │ step_2()    │
└─────────────┘     └──────┬──────┘     └──────┬──────┘
                           │                   │
                    information_complete      knowledge_context
                    /              \
                  否                是
                  /                  \
                 /                    ▼
           返回追问            ┌─────────────┐
           follow_up          │ 约束构建    │ step_3()
                              └──────┬──────┘
                                     │ constraints + region
                                     ▼
                              ┌─────────────┐
                              │ 食谱生成    │ step_4()
                              │ LLM生成JSON  │
                              └──────┬──────┘
                                     │ diet_plan
                                     ▼
                              ┌─────────────┐
                              │ 方案校验    │ step_5()
                              │ +自动修正    │
                              └──────┬──────┘
                                     │ final_diet_plan
                                     ▼
                              ┌─────────────┐
                              │ 结果输出    │ step_6()
                              └─────────────┘
                                     │
                                     ▼
                    {success, need_info, diet_plan, message}
```

**6个处理环节详解：**

| 步骤 | 方法 | 输入 | 输出 | 关键逻辑 |
|------|------|------|------|---------|
| 1 信息收集 | `step_collect_info()` | user_id, query | user_profile, information_complete | 4个核心字段缺失判定 |
| 2 知识检索 | `step_retrieve_knowledge()` | query + chronic | knowledge_context | 结合慢病类型检索 |
| 3 约束构建 | `step_build_constraints()` | profile | constraints + region | 文本化约束条件 |
| 4 食谱生成 | `step_generate_diet()` | 全部组装 → LLM | diet_plan | LCEL: Prompt→LLM→JsonParser |
| 5 方案校验 | `step_validate_diet()` | plan + profile | final_diet_plan | 不合规则LLM自动修正 |
| 6 结果输出 | `step_format_output()` | 全部结果 | 标准化响应 | 3分支：追问/失败/成功 |

**LCEL链式调用核心**：

```python
# 步骤4 食谱生成使用真正的LCEL管道
chain = DIET_GENERATE_PROMPT | self.llm | self.json_parser
diet_plan = await chain.ainvoke(prompt_input)

# 步骤5 修正方案也是独立LCEL管道
revise_chain = DIET_REVISE_PROMPT | self.llm | self.json_parser
revised_plan = await revise_chain.ainvoke(revise_input)
```

**自动修正机制**：
- 生成后立即调用 `validate_diet_plan()` 校验
- 如果发现禁忌食材，组装issues_text传给修正Prompt
- 修正后再次校验，最多尝试修正1次

**流式处理**（`process_stream()`）：
- 每个处理环节开始和完成都发出事件
- 事件格式：`{stage, status, message}`
- 最后一个 `output` 事件携带完整数据


**Redis实现细节**：
- 对话历史：`conversation:{user_id}:{session_id}` → Redis List（rpush + lrange）
- 用户偏好：`user_prefs:{user_id}` → Redis Hash（hgetall/hset）
- 膳食历史：`diet_history:{user_id}` → Redis List + ltrim限制30条
- 不可用时自动fallback到InMemoryStore，上层无感

**InMemoryStore实现细节**：
- 纯内存字典存储，无需外部依赖
- 完全相同的API：`get_conversation/add_message/clear_conversation`
- 开发环境首选，测试不需要Redis

**便捷函数**：
- `get_memory()` - 获取MemoryManager单例
- `get_conversation_history(user_id)` - 一行获取对话历史
- `save_interaction(user_id, user_msg, ai_msg)` - 一次保存完整交互

|---------|---------|---------|
| ConversationMemory类 | MemoryManager类 | 语义更清晰，增加LangChain兼容接口 |
