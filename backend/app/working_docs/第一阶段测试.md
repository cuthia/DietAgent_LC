## 一、测试目的

1. 验证多环境配置系统完整加载、合并、环境变量解析、Pydantic 校验逻辑正确性；
2. 验证密码 bcrypt 哈希/校验、JWT 签发/解析/过期/篡改校验整套安全流程可靠性；
3. 验证 FastAPI 分层架构、依赖注入鉴权逻辑、全局异常捕获机制有效性；
4. 验证 SQLAlchemy 2.0 异步 ORM 一对一表关系、自动时间字段、级联删除、CRUD 数据操作稳定性；
5. 验证全部用户、对话、健康检查接口输入输出、权限拦截逻辑符合设计规范；
6. 验证项目分层解耦设计无导入、路径、语法类运行故障；
7. 验证日志模块控制台输出、生产环境文件切分、异步写入功能正常；
8. 验证文件内 `if __name__ == "__main__"` 自测脚本可独立运行、覆盖核心纯函数逻辑。

## 二、测试环境说明

### 2.1 软件环境

- 操作系统：Windows 11
- Python 版本：3.10+（Anaconda 虚拟环境 `ragent`）
- Web 框架：FastAPI（ASGI 异步框架）
- ORM：SQLAlchemy 2.0（异步模式，`AsyncSession` + `select()` 2.0 风格查询）
- 数据库驱动：aiomysql（MySQL 异步驱动）
- 数据库：MySQL 8.x（数据库名 `dietapp`）
- 密码哈希：bcrypt 库（直接调用，非 passlib 封装）
- JWT 鉴权：python-jose
- 配置解析：自定义 YAML 加载器 + Pydantic BaseModel
- 日志框架：Loguru
- ASGI 服务器：uvicorn
- 接口调试工具：Swagger UI（`/docs`）/ Postman

### 2.2 工程环境

1. 源码根目录：`backend/app`，PyCharm 标记为 Sources Root
2. 环境标识：`ENV=dev` 默认加载 `config.yaml` + `config.dev.yaml`
3. 配置文件层级：公共 `config.yaml` + 环境专属配置文件递归合并
4. 运行方式：`uvicorn main:app --reload`（开发环境热重载）
5. 目录分层：基础设施层 `core` / 接口路由层 `api` / 数据持久层 `db` / 请求模型 `schemas`
6. 异步架构：全链路异步（`async def` 路由 + `AsyncSession` 数据库会话 + `aiomysql` 驱动）

### 2.3 文件内自测脚本运行方式

第一阶段在 5 个核心文件中内置了 `if __name__ == "__main__"` 自测脚本，可独立运行验证纯函数逻辑：

| 文件 | 自测内容 | 运行命令（在 `backend/app` 目录下） |
| ---- | ---- | ---- |
| `core/security.py` | 密码哈希/校验、JWT 生成/解析/过期/篡改 | `python -m core.security` |
| `core/config_handler.py` | 环境变量解析、配置合并、懒加载单例 | `python -m core.config_handler` |
| `core/exception.py` | 异常类属性、错误码、继承关系 | `python -m core.exception` |
| `schemas/common_schema.py` | 泛型响应模型序列化、默认值 | `python -m schemas.common_schema` |
| `schemas/user_schema.py` | Pydantic 字段校验、from_attributes 转换 | `python -m schemas.user_schema` |

> 说明：含相对导入的文件需用 `python -m 包.模块` 方式运行（而非直接 `python 文件名`），以确保包上下文正确。无相对导入的文件两种方式均可。

## 三、测试范围

### 3.1 基础设施模块

1. 多环境配置加载系统（YAML 合并 + 环境变量占位符解析 + Pydantic 校验）
2. Loguru 全局日志模块（控制台彩色输出 + 生产环境文件落盘）
3. 全局自定义异常处理模块（业务异常 + 参数校验异常 + 未知异常兜底）
4. 数据库异步会话连接管理（连接池 + 依赖注入 + 事务提交/回滚）

### 3.2 安全核心模块

1. bcrypt 密码哈希与校验（直接调用 bcrypt 库，72 字节截断处理）
2. JWT 令牌生成、解析、过期校验、篡改拦截

### 3.3 依赖注入鉴权模块

1. OAuth2 Bearer Token 提取依赖
2. 全局登录用户异步注入逻辑（`async def get_current_user`）
3. 未登录/非法 Token/用户不存在/用户已禁用 拦截逻辑

### 3.4 ORM 数据层模块（异步）

1. User、UserProfile 一对一模型映射（含 nullable 字段设计）
2. created_at / updated_at 自动填充与更新（UTC 时区）
3. 外键唯一约束、级联删除逻辑（`cascade="all, delete-orphan"`）
4. 用户异步 CRUD 操作（`select` + `execute` + `scalar_one_or_none`）

### 3.5 API 接口模块（异步路由）

1. 用户模块：注册（含空档案初始化）、登录、档案查询、档案更新
2. 对话模拟接口：消息发送鉴权拦截
3. 系统健康检查接口
4. Swagger 文档访问权限控制（仅 dev 环境开放）

### 3.6 工程规范测试

1. 模块导入路径无报错（含异步模块正确导入）
2. 类型注解、Pydantic 模型校验生效
3. 路由统一聚合、路径前缀 `/api` 生效
4. lifespan 生命周期正确初始化数据库

### 3.7 文件内自测脚本

1. `core/security.py`：密码哈希/校验、JWT 全流程（8 项断言）
2. `core/config_handler.py`：环境变量解析、配置合并、单例缓存（6 项断言）
3. `core/exception.py`：异常类属性与继承关系（5 项断言）
4. `schemas/common_schema.py`：泛型响应模型序列化（4 项断言）
5. `schemas/user_schema.py`：Pydantic 校验与 ORM 转换（5 项断言）

## 六、测试结论

1. **基础底座全部验收通过**：多环境配置、日志、全局异常、数据库异步 ORM、安全鉴权五大基础设施模块功能完全符合设计方案，逻辑闭环无阻断故障；
2. **用户业务模块完整可用**：注册（含空档案初始化）、登录、健康档案整套接口流程正常，鉴权拦截、参数校验、数据持久化行为符合需求；
3. **异步架构全链路打通**：`async def` 路由 → `AsyncSession` 依赖注入 → `select` + `await execute` 数据库操作，无同步/异步混用问题；
4. **安全模块稳定可靠**：bcrypt 密码哈希（直接调用库，无 passlib 兼容隐患）、JWT 签发/解析/过期/篡改全场景覆盖；
5. **分层架构解耦达标**：core 基础设施、api 接口层、db 数据层、schemas 请求模型分层清晰，导入、依赖注入流程稳定；
6. **异常分支全覆盖**：参数错误、未登录、令牌过期、数据不存在、用户禁用等异常场景均有统一响应处理，生产环境不会暴露系统内部信息；
7. **文件内自测脚本可用**：5 个核心文件内置 28 项断言，可独立运行快速验证纯函数逻辑，为后续 pytest 框架迁移奠定基础；
8. **扩展性预留完善**：当前架构支持第二阶段 RAG 向量知识库、第三阶段膳食 Agent 快速迭代开发，无需重构底层基础代码；
9. 整体满足第一阶段「最小可运行闭环」目标，可进入第二阶段 RAG 知识库开发工作。
