## 三、核心设计思路

### 3.1 向量嵌入模型设计

**设计原则：单例模式、懒加载、多源加载保障**

```
加载策略（优先级从高到低）：
┌─────────────────────────────────────────────────────────────┐
│ 1. 本地路径加载                                               │
│    local_path 存在 → SentenceTransformer(local_path)         │
├─────────────────────────────────────────────────────────────┤
│ 2. 在线镜像加载                                               │
│    设置 HF_ENDPOINT=https://hf-mirror.com                    │
│    → SentenceTransformer(model_name)                        │
├─────────────────────────────────────────────────────────────┤
│ 3. Mock降级模式                                               │
│    网络不可用 → 基于MD5哈希生成确定性随机向量                  │
│    保证功能测试可独立于网络运行                                │
└─────────────────────────────────────────────────────────────┘
```

**关键实现技巧：**
- `__new__` 实现多例缓存：`cache_key = f"{model_name}_{device}_{local_path}_{hf_endpoint}_{offline}"`
- 懒加载：首次调用 `embed()` 时才加载模型，避免启动阻塞
- `_mock_embed()` 使用 MD5 哈希作为随机种子，确保跨运行确定性
- `download_model()` 静态方法支持一键预下载

### 3.2 向量库统一接口设计

**设计原则：面向接口编程、工厂模式、开发/生产分离**

```
┌─────────────────────────────────────────────────────────────┐
│                    业务层（Retriever/Service）                │
└───────────────────────────┬─────────────────────────────────┘
                            │ 依赖抽象接口
┌───────────────────────────▼─────────────────────────────────┐
│                    抽象层                                     │
│                    BaseVectorStore (ABC)                      │
│                    add() / search() / delete() / clear()     │
└───────────────────────────┬─────────────────────────────────┘
                            │ 实现抽象接口
         ┌──────────────────┴──────────────────┐
         ▼                                     ▼
┌──────────────────┐                 ┌──────────────────┐
│ ChromaVectorStore│                 │MilvusVectorStore │
│   (开发环境)      │                 │   (生产环境)      │
└──────────────────┘                 └──────────────────┘
         │                                     │
         └───────────┬─────────────────────────┘
                     ▼
          create_vector_store() 工厂函数
          根据 config.type 动态创建
```

**关键实现技巧：**
- `BaseVectorStore` 使用 ABC 抽象基类，定义 5 个核心方法
- 工厂函数 `create_vector_store()` 根据配置动态实例化
- 统一的 `Document` 返回格式，包含 id/content/metadata
- Chroma 使用 `PersistentClient` 支持持久化存储

### 3.3 文档处理流水线设计

**设计原则：流水线模式、策略模式、可扩展**

```
┌─────────────────────────────────────────────────────────────┐
│                    文档入库流水线                              │
│                                                             │
│  原始文档 ──→ DocumentLoader ──→ 文本提取 ──→ TextSplitter  │
│               (策略模式)        (清洗/元数据)    (递归分块)   │
│                                                   │         │
│                                                   ▼         │
│                                              分块列表       │
│                                                   │         │
│                                                   ▼         │
│  ┌─────────────────────────────────────────────────────┐    │
│  │              EmbeddingModel                         │    │
│  │  每个块向量化 → 获取向量列表                         │    │
│  └─────────────────────────────────────────────────────┘    │
│                                                   │         │
│                                                   ▼         │
│  ┌─────────────────────────────────────────────────────┐    │
│  │              BaseVectorStore                         │    │
│  │  向量 + 元数据 → 存入向量库                          │    │
│  └─────────────────────────────────────────────────────┘    │
└─────────────────────────────────────────────────────────────┘
```

**关键实现技巧：**
- `DocumentLoader` 使用策略模式：`self.parsers = {".md": self._parse_markdown, ...}`
- 文本清洗：正则去除多余空格、特殊控制字符、统一换行符
- `TextSplitter` 递归分块：优先按段落/句号分割，保证语义完整性
- 重叠分块：`chunk_overlap` 避免上下文丢失
- 文档元数据保留：分块后携带原始文档的 id/category/metadata

### 3.4 检索器设计

**设计原则：两阶段检索、可选重排、类别过滤**

```
检索流程：
┌─────────────────────────────────────────────────────────────┐
│ 1. 查询文本 → embed(is_query=True) → 查询向量                │
│    (BGE模型自动添加 "query: " 前缀)                          │
│                                                             │
│ 2. 向量库相似度检索（召回 Top-K 候选）                       │
│    → vector_store.search(query, top_k=recall_count)         │
│                                                             │
│ 3. 重排优化（可选，使用 CrossEncoder）                        │
│    → 对召回结果精排，提升精度                                 │
│                                                             │
│ 4. 返回最终 Top-N 结果                                      │
│    → 按相关性排序，携带分数和元数据                           │
└─────────────────────────────────────────────────────────────┘
```

**关键实现技巧：**
- BGE 模型查询向量需加 `"query: "` 前缀，与文档向量区分
- 支持类别过滤：`category` 参数精准定位知识领域
- 两阶段检索：粗召回（大 top_k）+ 精重排（小 top_k）
- 结果包含相似度分数，便于阈值过滤

## 八、风险与应对

### 8.1 网络访问问题

**风险**：国内无法直接访问 HuggingFace

**应对**：
- 默认配置 `hf_endpoint: "https://hf-mirror.com"` 使用国内镜像
- 支持 `local_path` 从本地加载已下载模型
- Mock 降级模式保证功能测试独立运行
- 提供 `download_model()` 静态方法一键预下载

### 8.2 内存占用

**风险**：大批量文档向量化时内存不足

**应对**：
- 分批处理（每批100条）
- 使用生成器逐步处理
- 考虑异步任务（后续阶段实现）

### 8.3 检索效果

**风险**：召回率低或准确率低

**应对**：
- 优化分块策略（已实现语义分块）
- 添加重排（CrossEncoder，已预留接口）
- 支持类别过滤精准检索
- 调整检索参数（top_k、相似度阈值）
