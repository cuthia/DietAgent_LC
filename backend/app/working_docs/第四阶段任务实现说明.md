```python
def chat_stream(self, message: str) -> Generator[Dict, None, None]:
    """流式对话（SSE）"""
    response = requests.post(url, json=payload, headers=headers, stream=True)
    
    # 解析 SSE 事件流
    for line in response.iter_lines(decode_unicode=True):
        if line.startswith("data: "):
            data_str = line[6:]  # 去掉 "data: " 前缀
            if data_str == "[DONE]":
                break
            event = json.loads(data_str)
            yield event
```

2. **单例模式**：
```python
_api_client: Optional[APIClient] = None

def get_api_client() -> APIClient:
    """获取全局 API 客户端实例"""

    if _api_client is None:
        _api_client = APIClient()
    return _api_client
```

## 三、技术亮点总结

### 3.1 SSE 流式响应处理

**挑战**：Streamlit 的 `st.rerun()` 机制与流式输出冲突

**解决方案**：
```python
# 使用 placeholder 动态更新
with st.chat_message("assistant"):
    progress_placeholder = st.empty()
    plan_placeholder = st.empty()
    text_placeholder = st.empty()

    # 流式更新进度
    for event in api.chat_stream(message):
        progress_placeholder.write(event["message"])
        # 动态渲染方案卡片
        if event.get("diet_plan"):
            with plan_placeholder.container():
                render_diet_plan_card(event["diet_plan"])
```

### 3.2 会话状态持久化

**挑战**：Streamlit 每次交互都重新运行脚本，状态易丢失

**解决方案**：
- 使用 `st.session_state` 持久化关键状态
- API 客户端单例模式（避免重复创建）
- 组件内部状态管理

### 3.3 组件化设计

**优势**：
- `diet_card.py` 可在对话页、历史页复用
- `user_form.py` 支持编辑/查看两种模式
- `nutrition_chart.py` 可选依赖降级

### 3.4 前后端解耦

**优势**：
- API 客户端封装层隔离后端变更
- UI 组件纯展示，不包含业务逻辑
- 便于单元测试和维护
