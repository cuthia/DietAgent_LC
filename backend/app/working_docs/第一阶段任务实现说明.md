## 三、核心设计思路

### 3.1 配置系统设计

**设计原则：配置与代码分离、多环境隔离、敏感信息保护**

```
配置加载流程：
┌─────────────────┐    ┌──────────────────┐    ┌─────────────────┐
│ config.yaml     │    │ config.dev.yaml  │    │ config.prod.yaml│
│ （基础配置）     │    │ （开发环境）      │    │ （生产环境）     │
└────────┬────────┘    └────────┬─────────┘    └────────┬────────┘
         │                      │                       │
         └──────────┬───────────┴───────────┬───────────┘
                    ▼                       ▼
           ┌──────────────┐         ┌──────────────┐
           │  _load_yaml  │         │ _merge_configs│
           │   _resolve_env_vars     │ （递归合并） │
           └────────┬─────┘         └──────┬───────┘
                    │                      │
                    └──────────┬───────────┘
                               ▼
                     ┌──────────────────┐
                     │  Settings(**dict)│
                     │  （Pydantic校验） │
                     └────────┬─────────┘
                              ▼
                     ┌──────────────────┐
                     │   config_api.py  │
                     │   统一导出接口    │
                     └──────────────────┘
```

**关键实现技巧：**
- 使用 `ENV_PATTERN` 正则解析 `${VAR:default}` 占位符
- 递归解析嵌套结构中的环境变量
- Pydantic模型提供类型校验和默认值
- `@lru_cache()` 确保配置只加载一次
- `@property` 实现懒加载模式

### 3.2 安全模块设计

**设计原则：密码安全存储、令牌无状态认证、最小权限原则**

```
密码流程：
┌─────────────────────────────────────────────────────────────┐
│ 注册：password → hash_password() → bcrypt哈希 → 存储        │
│ 登录：password → verify_password() → 比对哈希 → 验证通过     │
└─────────────────────────────────────────────────────────────┘

JWT流程：
┌─────────────────────────────────────────────────────────────┐
│ 创建：user_id → {"sub": id, "exp": time} → jwt.encode()    │
│ 解析：token → jwt.decode() → {"sub": id} → 查询用户        │
└─────────────────────────────────────────────────────────────┘
```

**关键实现技巧：**
- 使用 `passlib.CryptContext` 封装密码哈希
- JWT负载只存储必要信息（用户ID）
- 令牌过期时间由配置控制
- 解码失败统一返回None，由调用方处理

### 3.3 依赖注入设计

**设计原则：解耦认证逻辑、复用鉴权代码、自动依赖注入**

```
依赖注入链：
┌─────────────────────────────────────────────────────────────┐
│ @router.get("/profile")                                     │
│ def get_profile(current_user: User = Depends(get_current_user)): │
│     └── Depends(get_current_user)                           │
│         ├── Depends(oauth2_scheme) → token                  │
│         └── Depends(get_db) → db_session                    │
│             └── decode_access_token(token) → user_id        │
│             └── get_user_by_id(db, user_id) → user         │
│             └── 返回 user 对象                              │
└─────────────────────────────────────────────────────────────┘
```

**关键实现技巧：**
- `OAuth2PasswordBearer` 自动从请求头提取令牌
- `Depends()` 构建依赖链，自动注入参数
- 认证失败抛出 `AuthFailedException`，由全局处理器统一处理

### 3.4 异常处理设计

**设计原则：统一响应格式、分层异常处理、安全日志记录**

```
异常处理层次：
┌─────────────────────────────────────────────────────────────┐
│ 业务异常（BusinessException）                               │
│   ├── UserNotExistException (40001)                        │
│   ├── AuthFailedException (40101)                          │
│   └── ParamsException (40000)                              │
│       → business_exception_handler → {"code": xxx, ...}    │
├─────────────────────────────────────────────────────────────┤
│ 参数校验异常（RequestValidationError）                      │
│   → validation_exception_handler → {"code": 40000, ...}    │
├─────────────────────────────────────────────────────────────┤
│ 全局未知异常（Exception）                                    │
│   → global_exception_handler → {"code": 50000, ...}        │
│     （不泄露堆栈信息，只记录日志）                            │
└─────────────────────────────────────────────────────────────┘
```

**关键实现技巧：**
- 自定义异常继承 `BusinessException`，携带错误码和消息
- 全局处理器统一捕获，返回标准格式响应
- 生产环境隐藏详细错误信息，保护系统安全

### 3.5 数据库设计

**设计原则：ORM映射、关系管理、事务控制**

```
表关系：
┌────────────────┐      1:1       ┌──────────────────┐
│    User        │◄───────────────│   UserProfile    │
├────────────────┤                 ├──────────────────┤
│ id (PK)        │                 │ id (PK)          │
│ username       │                 │ user_id (FK)     │
│ password_hash  │                 │ age              │
│ is_active      │                 │ gender           │
│ created_at     │                 │ height           │
│ updated_at     │                 │ weight           │
└────────────────┘                 │ taste_preference │
                                   │ food_taboo       │
                                   │ chronic_disease  │
                                   │ region           │
                                   │ diet_goal        │
                                   └──────────────────┘
```

**关键实现技巧：**
- 使用SQLAlchemy ORM，避免手写SQL
- `flush()` 获取自增ID，用于创建关联记录
- `commit()` 统一提交事务
- `refresh()` 刷新对象状态，确保数据最新

# 调试时修改点

## 1. byrupt

表面现象 ：注册接口返回 500，报 password cannot be longer than 72 bytes

真实原因： passlib 1.7.4（2020 年后停止维护）与新版 bcrypt 4.x 不兼容 

触发位置： 不是你的密码太长，而是 passlib 初始化时 用长密码做内部 bug 检测，新版 bcrypt 直接抛异常 

为什么截断： try/except 无效 错误发生在 passlib 的 detect_wrap_bug 内部，每次调用都重新触发，你的 except 分支同样会失败

### 修改内容
security.py 改动：

1. 移除 passlib 依赖 ：删掉 from passlib.context import CryptContext 和 pwd_context
2. 直接用 bcrypt 库 ： import bcrypt ，用 bcrypt.hashpw() / bcrypt.checkpw()
3. hash_password ： encode → 截断 72 字节 → gensalt → hashpw → decode
4. verify_password ： encode → 截断 → checkpw （checkpw 会自动从哈希里提取盐值比对）
5. JWT 部分完全不动 （python-jose 没有兼容性问题）





## 2. 用户表字段nullable=True

在 SQLAlchemy 2.0 中， Mapped[int] （非 Optional）会自动推断 nullable=False 。所以数据库里这些字段不允许为空。

但你的业务逻辑是： 注册时创建空的健康档案 （用户后续通过 update_profile 接口填写），所以 INSERT 时这些字段全是 None → 违反 NOT NULL 约束 → 报 Column 'age' cannot be null 。

你的 schema 设计（ UserProfileUpdateRequest / UserProfileResponse 都用 Optional ）也证实了设计意图就是允许空，只是 model 定义漏了。

必须允许为 null ：注册时创建的是 空档案 （用户还没填任何健康信息），所有字段都是 None，后续通过 PUT /api/user/profile 接口逐步填写。这与你的 schema 设计（ UserProfileUpdateRequest 全是 Optional ）是一致的。
