### 任务3.2：向量库统一接口封装（高优先级）

**目标**：封装向量库操作，支持Chroma和Milvus切换

**文件路径**：`backend/app/rag/vector_store.py`

**实现要点**：

```python
# 抽象基类设计
class BaseVectorStore(ABC):
    """
    向量库抽象基类
    
    定义统一接口，上层依赖抽象而非具体实现
    切换向量库无需修改业务代码
    """
    
    @abstractmethod
    def add(self, texts: List[str], metadatas: Optional[List[Dict]] = None) -> List[str]:
        """添加文档向量"""
        ...
    
    @abstractmethod
    def search(self, query: str, top_k: int = 5) -> List[Document]:
        """相似度检索"""
        ...
    
    @abstractmethod
    def delete(self, ids: List[str]) -> None:
        """删除文档"""
        ...
    
    @abstractmethod
    def clear(self) -> None:
        """清空向量库"""
        ...
    
    @abstractmethod
    def count(self) -> int:
        """文档数量"""
        ...


# Chroma实现
class ChromaVectorStore(BaseVectorStore):
    """Chroma向量库实现（开发环境）"""
    ...


# Milvus实现
class MilvusVectorStore(BaseVectorStore):
    """Milvus向量库实现（生产环境）"""
    ...


# 工厂函数
def create_vector_store(store_type: str, **kwargs) -> BaseVectorStore:
    """根据配置创建向量库实例"""
    ...
```

**关键技术点**：
- 使用抽象基类定义接口规范
- 工厂模式根据配置动态选择实现
- Chroma适合开发（轻量级、无需额外服务）
- Milvus适合生产（高性能、分布式）
- 统一的 `Document` 返回格式

**测试验证**：
- Chroma模式：添加文档、检索、删除、清空
- Milvus模式：连接测试、集合创建、数据写入
- 切换配置验证两种模式无缝切换

## 六、技术选型理由

### 6.1 向量模型：BGE

| 对比项 | BGE | OpenAI Embedding |
|--------|-----|-----------------|
| 中文效果 | 优秀（中文专用） | 一般 |
| 部署方式 | 本地部署 | API调用 |
| 成本 | 免费 | 按token计费 |
| 隐私 | 数据本地化 | 数据上传第三方 |

### 6.2 向量库：Chroma vs Milvus

| 对比项 | Chroma | Milvus |
|--------|--------|--------|
| 部署难度 | 简单（Python包） | 复杂（独立服务） |
| 性能 | 一般（适合开发） | 优秀（分布式） |
| 扩展性 | 有限 | 无限水平扩展 |
| 适用场景 | 开发/测试 | 生产环境 |

### 6.3 文档解析工具

| 格式 | 推荐库 | 理由 |
|------|--------|------|
| PDF | PyPDF2 / pdfplumber | PyPDF2轻量，pdfplumber解析更准确 |
| Markdown | markdown | 标准库，解析准确 |
| Word | python-docx | 官方推荐，功能完整 |
| TXT | 内置open() | 无需额外依赖 |

- 支持从本地路径加载
- 配置中添加模型路径选项

### 9.2 内存占用过高

**风险**：大批量文档向量化时内存不足

**应对**：
- 分批处理（每批100条）
- 使用生成器逐步处理
- 考虑异步任务（Celery）

### 9.3 检索效果不佳

**风险**：召回率低或准确率低

**应对**：
- 优化分块策略
- 添加重排（CrossEncoder）
- 调整检索参数（top_k、相似度阈值）
- 扩充知识库文档数量

### 9.4 Milvus部署复杂

**风险**：生产环境Milvus部署困难

**应对**：
- 提供Docker Compose配置
- 开发阶段使用Chroma
- 准备Milvus部署文档

## 十二、总结

第二阶段的核心目标是构建完整的RAG知识库模块，为后续Agent提供专业的膳食知识检索能力。

**关键设计原则**：
1. **面向接口编程**：向量库抽象封装，支持无缝切换
2. **分层解耦**：文档处理、向量化、检索、API严格分离
3. **开发/生产分离**：Chroma用于开发，Milvus用于生产
4. **可扩展性**：预留重排、过滤、异步处理等扩展点

**面试亮点**：
- BGE中文向量模型选择（体现技术选型能力）
- 向量库抽象设计（体现架构思维）
- 完整的文档处理流水线（体现工程能力）
- 多格式文档支持（体现项目完备性）

完成此阶段后，项目将具备专业的膳食知识检索能力，为第三阶段Agent核心开发打下坚实基础。
