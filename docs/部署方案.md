## 1. 最终效果

部署完成后，系统同时提供三种访问方式：

| 访问方式 | 地址 | 用途 |
|---------|------|------|
| 本地开发 | `http://127.0.0.1:8501` | 你自己开发调试，行为与现在完全一致 |
| 国内朋友 | cpolar 随机 HTTPS 地址 | 国内网络访问，免费版即可 |
| 国外朋友 | `https://diet.cuthiadev.asia` | 正式长期访问，Cloudflare Tunnel 提供 HTTPS |

三种方式共用同一套 Docker 容器，不需要分别部署三份服务。

## 2. 免费政策确认

### 2.1 cpolar

已核对 cpolar 官网定价页（2026-08-17）：

- 免费版永久免费。
- 带宽 1 Mbps。
- 随机 URL 二级域名。
- 支持 HTTP / TCP 隧道。
- 每个在线 cpolar 进程最多 4 条隧道。
- 官网标注所有套餐不限制流量。

结论：**免费版可以免费使用**，适合国内演示；速度受 1 Mbps 带宽限制，不适合大量并发。

### 2.2 Cloudflare Tunnel

已核对 Cloudflare 官方文档（2026-08-17）：

- Cloudflare Tunnel 服务本身免费。
- 免账号 Quick Tunnel 免费，但官方明确仅限测试，且**不支持 SSE**；本项目聊天依赖 SSE 流式输出，所以不使用 Quick Tunnel。
- 生产级 named tunnel 免费，但要求域名已托管到 Cloudflare。

你已有域名 `cuthiadev.asia`，因此 Cloudflare 正式通道可以**完全免费**实现，使用子域名：

```text
diet.cuthiadev.asia
```

## 3. 总体架构

```text
你本机（Windows）
│
├─ Docker 容器
│  ├─ frontend 容器  8501 端口（页面 + API 反向代理）
│  ├─ backend 容器   8000 端口（FastAPI）
│  ├─ mysql 容器     仅 Docker 内网
│  └─ redis 容器     仅 Docker 内网
│
├─ cpolar 进程（可选启动）
│  └─ 国内朋友 ── https://随机域名.cpolar.top ──> 127.0.0.1:8501
│
└─ cloudflared 进程（可选启动）
   └─ 国外朋友 ── https://diet.cuthiadev.asia ──> 127.0.0.1:8501
```

关键设计：

- 公网只暴露 `8501` 一个入口。
- `/api/*`、`/health` 由 frontend 容器反向代理到 `backend:8000`。
- MySQL、Redis 不对外，安全性保持现状。
- 本地开发继续用 `http://127.0.0.1:8501`，前端请求同一域名下的 `/api`，同样走反向代理，行为一致。

## 4. 核心代码改造

实施阶段需要改两个前端文件，并重建 frontend 容器。

### 4.1 `frontend/server.js`：增加反向代理

在现有 Node 静态服务器中增加代理规则：

| 请求路径 | 转发目标 |
|---------|---------|
| `/api/*` | `http://backend:8000/api/*` |
| `/health` | `http://backend:8000/health` |
| `/agent/*`（天气功能兼容） | `http://backend:8000/agent/*` |

代理实现要求：

- 透传请求方法、请求头、请求体。
- 透传响应头。
- **不能缓冲 SSE**：`/api/agent/chat/stream` 必须逐块转发，保证聊天打字机效果。
- 代理失败时返回 `502`，方便排查。

### 4.2 `frontend/app.js`：API 地址改为同源

当前：

```js
const API_BASE = "http://127.0.0.1:8000";
```

改为：

```js
const API_BASE = (window.__DIETAGENT_API_BASE__ || "").replace(/\/$/, "");
```

作用：

- 本地访问 `http://127.0.0.1:8501` 时，请求 `http://127.0.0.1:8501/api/...`。
- cpolar 访问时，请求 cpolar 域名下的 `/api/...`。
- Cloudflare 访问时，请求 `https://diet.cuthiadev.asia/api/...`。
- 不再依赖访问者电脑上的 `127.0.0.1:8000`。

### 4.3 重建前端容器

```powershell
docker compose up -d --build frontend
```

`docker-compose.yml` 可以保持不变，保留 `8000:8000` 给本地开发直接调试 API。

### 4.4 可选：新增运维脚本

建议新增 `scripts/` 目录：

| 脚本 | 作用 |
|------|------|
| `start-dev.ps1` | `docker compose up -d` |
| `start-cpolar.ps1` | 启动 cpolar 隧道 |
| `start-cloudflare.ps1` | 启动 Cloudflare Tunnel |
| `stop-tunnels.ps1` | 停止两条隧道 |

## 6. Cloudflare Tunnel 配置（国外朋友）

### 6.1 前提检查

确认以下条件：

- [ ] 域名 `cuthiadev.asia` 已在 Cloudflare 免费套餐中添加。
- [ ] 域名注册商处的 DNS 已改为 Cloudflare 提供的两个 Nameserver。
- [ ] Cloudflare 后台显示域名状态为 Active。

如果域名还没有接入 Cloudflare：

1. 打开 https://dash.cloudflare.com，点击 Add a site。
2. 输入 `cuthiadev.asia`，选择 Free 套餐。
3. 按提示添加 DNS 记录（可以先只加一条，后续 tunnel 会自动加）。
4. 记下 Cloudflare 分配的两个 Nameserver。
5. 去你购买 `.asia` 域名的注册商后台，把 NS 修改为 Cloudflare 的 Nameserver。
6. 等待状态变为 Active，通常几分钟到 24 小时。

### 6.2 安装 cloudflared

Windows 推荐用 winget：

```powershell
winget install --id Cloudflare.cloudflared
```

安装后验证：

```powershell
cloudflared --version
```

### 6.3 登录并授权

```powershell
cloudflared tunnel login
```

浏览器会打开 Cloudflare 登录页，选择 `cuthiadev.asia` 并授权。

### 6.4 创建隧道

```powershell
cloudflared tunnel create dietagent
```

成功后会显示 Tunnel ID，并在以下目录生成凭据文件：

```text
C:\Users\<你的用户名>\.cloudflared\<隧道ID>.json
```

### 6.5 绑定域名

```powershell
cloudflared tunnel route dns dietagent diet.cuthiadev.asia
```

这会自动在 Cloudflare DNS 中创建一条 CNAME 记录：

```text
diet.cuthiadev.asia  ->  <隧道ID>.cfargotunnel.com
```

### 6.6 编写 cloudflared 配置

编辑文件：

```text
C:\Users\<你的用户名>\.cloudflared\config.yml
```

内容：

```yaml
tunnel: dietagent
credentials-file: C:\Users\<你的用户名>\.cloudflared\<隧道ID>.json

ingress:
  - hostname: diet.cuthiadev.asia
    service: http://127.0.0.1:8501
  - service: http_status:404
```

注意：把 `<你的用户名>` 和 `<隧道ID>` 替换成实际值。

### 6.7 启动隧道

前台启动：

```powershell
cloudflared tunnel run dietagent
```

验证：

```powershell
curl.exe -I https://diet.cuthiadev.asia/
curl.exe https://diet.cuthiadev.asia/health
```

`/health` 应返回后端健康检查 JSON，页面应返回 DietAgent HTML。

### 6.8 可选：开机自动运行

```powershell
cloudflared service install
```

这会注册为 Windows 服务，开机自动运行 `config.yml` 中的隧道。如果不需要常驻，可以跳过。

## 7. cpolar 配置（国内朋友）

### 7.1 安装

从 cpolar 官网下载 Windows 版本并安装。

### 7.2 注册并绑定令牌

1. 注册 cpolar 账号。
2. 在后台复制 authtoken。
3. 执行：

```powershell
cpolar authtoken <你的authtoken>
```

### 7.3 启动 HTTP 隧道

```powershell
cpolar http 8501
```

终端会输出公网地址，例如：

```text
https://xxxxxxxx.cpolar.top
```

把这个地址发给国内朋友。

### 7.4 验证

```powershell
curl.exe -I https://xxxxxxxx.cpolar.top/
curl.exe https://xxxxxxxx.cpolar.top/health
```

### 7.5 cpolar 免费版限制

- 带宽 1 Mbps，页面和流式聊天会偏慢。
- 随机域名，重启 cpolar 后地址可能变化。
- 保持 cpolar 终端窗口不要关闭。
- 实施后必须实测 `/api/agent/chat/stream`，确认 SSE 流式输出正常。

## 10. 安全注意事项

- MySQL `3306`、Redis `6379` 保持仅在 Docker 内网，不对外发布。
- 公网入口只暴露 `8501`，不要把后端 `8000` 暴露给公网。
- 公网使用前更新 `.env`：
  - MySQL 密码。
  - JWT Secret。
  - 确认 DeepSeek API Key 有效。
- cpolar 地址为随机域名，演示结束后停止进程即可关闭入口。
- Cloudflare 正式地址会长期可用，建议后续用 Cloudflare Access 或登录限制保护。
- 公网聊天会真实调用 DeepSeek API，注意 API 额度。

## 11. 常见问题

### 11.1 为什么不能用 `localhost:8501`？

本机 `localhost` 会优先解析到 IPv6 `::1`，当前机器上有进程占用了 `::1:8501`。统一使用：

```text
http://127.0.0.1:8501
```

### 11.2 为什么 Quick Tunnel 不能用？

Cloudflare Quick Tunnel 官方明确不支持 SSE，聊天打字机输出会失效，因此本项目使用 named tunnel。

### 11.3 cpolar 免费版地址变了怎么办？

免费版地址是随机的，重启后变化。演示时保持进程运行；需要固定地址可升级 cpolar 付费套餐。

### 11.4 前端改了代码，为什么页面没变化？

需要重新构建前端容器：

```powershell
docker compose up -d --build frontend
```

### 11.5 隧道能同时开吗？

可以。cpolar 和 cloudflared 都是主动向外连接，可以同时运行，都指向 `127.0.0.1:8501`。
